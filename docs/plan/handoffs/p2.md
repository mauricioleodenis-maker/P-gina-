# Handoff P2 (BD, RLS, cifrado, tipos)

Para Integracion / otros paquetes:
- Ejecutar SQL de P2: `bash supabase/tests/run.sh` (usa PG16 local; en CI hace falta `postgresql-16` o servicio postgres y ajustar `PG_BIN`). P10: anadir paso de CI "RLS" que lo ejecute. Entra tambien `supabase db lint` si hay CLI.
- `supabase/tests/00_shim.sql` simula roles/auth de Supabase: SOLO para el Postgres de pruebas.
- Contratos de BD:
  - `request_appointment(...)` y `busy_slots(...)` solo `service_role` (cliente `admin.ts`). Errores con `raise exception`: consent_required, too_soon, too_far, invalid_service, invalid_email, invalid_name, invalid_modality; solape/doble reserva = SQLSTATE `23P01` (exclusion_violation). Firma completa en `src/types/database.ts`.
  - `issue_invoice(...)` la llama el admin (aal2) con su cliente; `invoice_counters` es solo lectura para authenticated. Una factura emitida no se edita (solo `pdf_path`, `status`->void); corregir con rectificativa (`p_series='R'`, `p_rectifies`).
  - `audit_log`: authenticated puede INSERT/SELECT; UPDATE/DELETE/TRUNCATE bloqueados. Triggers de auditoria en patients, session_notes, payments, invoices (sin contenido).
  - `profiles` se lee con el cliente del usuario en aal1 (solo la propia fila) para el middleware.
  - Busqueda sin acentos: indice `public.f_unaccent(lower(full_name))` trigram; consultar con `f_unaccent(lower(full_name)) ilike f_unaccent(lower('%q%'))` via RPC o `.filter` (P6 decide; si necesita una RPC `search_patients`, crear `0060_patients.sql`).
  - Una solicitud `requested` ocupa el hueco (EXCLUDE) hasta rechazarla/cancelarla: P7 debe marcarla `cancelled` al rechazar.
- Cifrado: usar `encryptNote/decryptNote` + `toPgBytea/fromPgBytea` de `@/lib/crypto` (P6). Doc: `docs/plan/crypto.md`. Para staging anadir en `.env.example` (P0) opcionalmente `CLINICAL_ENCRYPTION_KEY_V<n>` solo durante rotaciones.
- `supabase/config.toml`: `[db] major_version = 15` (ajustar a la del proyecto Supabase); signups desactivados, jwt 1 h, min password 12. HIBP, MFA TOTP obligatorio y caducidad de sesion 30 min se configuran en el dashboard / middleware (P3).
- Pendiente de revision de P0: `src/components/motion/DrawLine.tsx` (P1) rompe `tsc` (SVGSVGElement vs HTMLElement), no es de P2.
- `src/types/database.ts` no se genero con CLI (no disponible): reflejar cualquier cambio de esquema a mano o regenerar en Integracion con `supabase gen types`.
