# Handoff P8 (Ingresos y facturas)

1. Rutas: `/admin/ingresos` (resumen, graficos con tabla alternativa, pendientes, cobros, CSV) y `/admin/ingresos/facturas` (emitir, PDF, enviar, rectificar). API: `/api/invoices/[id]/pdf` y `/api/invoices/export?type=payments|invoices&month=yyyy-MM` (CSV `;` con BOM y escape de formulas; auditado).
2. Contrato appointments (P7): al marcar una cita como realizada, llamar a `createChargeForAppointment(appointmentId)` de `@/modules/billing/api` (idempotente; falla si precio 0 o ya cobrada: capturar el error). `getPendingCharges` ya lista citas `completed` con saldo aunque no se llame.
3. Rectificativas: `invoices` exige importes >= 0 (CHECK), asi que la serie R refleja el importe de la original (sin signo) y la original pasa a `void`; los cobros quedan liberados para refacturar. Si se quiere importe negativo hace falta migracion `0080_p8.sql` (P2/Integracion). No se creo.
4. Datos fiscales: el snapshot sale de `practice_settings` (P3 Ajustes). Mientras falten NIF/direccion/IVA el PDF muestra `TODO_REAL`.
5. Bucket `invoices`: el PDF se guarda al emitir; si falla, se regenera bajo demanda en la ruta PDF.
6. Email de factura usa Resend (`RESEND_API_KEY`, `EMAIL_FROM`); asunto neutro sin datos clinicos.
7. Dependencias nuevas: ninguna. `src/types/database.ts`: ver handoff P3 punto 1 (`type` en vez de `interface`); billing usa cliente suelto `db()`.
8. P9 (dashboard) puede usar `getRevenueSeries`, `getRevenueReport`, `getPendingCharges`.
9. Correcciones menores en archivos propios para `noUncheckedIndexedAccess` (api.ts, calc.ts, test).
10. e2e: `e2e/p8/billing.spec.ts` solo humo sin credenciales.
